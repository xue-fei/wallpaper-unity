# 2026-11-02 工作日志

## 壁纸程序：修复 Explorer 重启后壁纸不恢复（进程重启链路）

### 根因（已实测确认）
- 壁纸窗口是 Explorer 桌面层 `WorkerW` 的子窗口；Explorer 重启时 `DestroyWindow` **递归销毁子窗口**，
  本进程的 Unity 窗口一并被销毁（实测 `IsWindow=False`、`GetWindowLong` 返回 0）。
- 因此**原进程内无法"重新挂接"**（窗口已不存在），只能重启进程。

### 之前两种重启方式都失败的原因
- `System.Diagnostics.Process.Start`：IL2CPP 打包后 **无论 UseShellExecute=true/false** 都抛
  `Win32Exception("Native error= Success")`，异常中 `CommandLine=''` 为空 → 托管侧构造命令行失败，
  根本没走到 Win32 `CreateProcess`。
- `ShellExecute`：实测返回 `42`（>32 看似成功），但**进程并未真正创建**。
  判据：Unity 启动即把 `Player.log` 轮转为 `Player-prev.log`（Windows 重命名保留 mtime）。
  事发后 `Player-prev.log` mtime 仍是上一个会话的时间 → 新进程从未走到 Unity 初始化。
  推断：ShellExecute 要经过 Shell（Explorer）解析动词，Explorer 重启瞬间 Shell 处于过渡状态。

### 本次修改（最终方案）
- `User32.cs` 新增：
  - `CreateProcess` P/Invoke + `STARTUPINFO` / `PROCESS_INFORMATION` 结构体
  - `CREATE_BREAKAWAY_FROM_JOB = 0x01000000`
  - `WAIT_TIMEOUT = 0x00000102`
- `WallpaperController.RelaunchSelf()` 重写：
  1. 首选 `CreateProcess`（先试 `CREATE_BREAKAWAY_FROM_JOB`，失败再退化普通调用），
     最多重试 3 次；
  2. 每次创建后用 `IsProcessAlive(pid, 8000)` 确认新实例**存活**才让旧进程退出；
  3. 全部失败后退化 `ShellExecute` 兜底。
- 新增 `TryCreateProcess()` / `IsProcessAlive()` 两个 helper。
- 看门狗在重启失败时输出 `[Watchdog] 自动重启失败，壁纸未恢复！`。
