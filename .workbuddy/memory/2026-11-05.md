## 桌面幻灯片守卫（方案 A）—— 彻底解决「每 30 分钟重启」

### 根因（已实测确认）
Windows 桌面背景「幻灯片放映」周期性切换壁纸，注册表
`HKCU:\Control Panel\Personalization\Desktop Slideshow` 的 `Interval = 1800000`（毫秒 = 30 分钟）。
切换时 Explorer 重刷桌面（Progman → WorkerW 重建），递归销毁子窗口（Unity 壁纸窗口），
触发 `NotifyIconItem.WndProc` 的 `WM_DESTROY` → `RelaunchSelf("窗口销毁")`。
日志 15:00:01 与 `LastTick` 解析出的 2026-11-05 15:00:00 完全吻合。

排除项：Explorer 崩溃/重启（PID 11676 连续运行 49 小时）、计划任务、锁屏、屏保、Windows 聚焦
（`DesktopSpotlight\Settings\EnabledState = 0`）。

### 新增文件
`Assets/Scripts/HardCode/Wallpaper/DesktopSlideshowGuard.cs`
- 运行期用 P/Invoke（advapi32）读写注册表（Unity IL2CPP 下 `Microsoft.Win32.Registry` 不可用）
- `OnWallpaperStart()`：① 有残留保存值则先还原 → ② 记录当前 `BackgroundType` 到
  `HKCU\Software\xuefei\WallPaper\SavedBackgroundType` → ③ 若为幻灯片(2)/聚焦(3) 则改为图片(0)
- `OnWallpaperStop()`：恢复保存值 + 删除保存值 + 广播 `WM_SETTINGCHANGE("Wallpapers")` 让 Explorer 立即生效
- `s_Restored` 静态防重复恢复；`Application.isEditor` 时整段跳过（不动系统设置、不污染工程）
- 只改动 2/3，图片(0)/纯色(1) 原样保留

### 挂载点（5 处，全部加 `DesktopSlideshowGuard`）
`WallpaperController.cs`
- `Start()`：`RestartLogger.WriteStartup()` 之后 `OnWallpaperStart()`
- `OnApplicationQuit()`：方法开头 `OnWallpaperStop()`（在 `m_QuitRequested` 判断之前）
- `OnDestroy()`：`UninstallMouseHook()` 之前 `OnWallpaperStop()`
- `Update()` 的 `m_SelfTerminate` 分支：`TerminateProcess` 之前 `OnWallpaperStop()`

## 方案 B：改挂 Progman（壁纸自愈）—— 替代方案 A 的根因修复

### 结论：方案 A 不够，方案 B 才是根因修复
- Win11 build 26300 已移除 `IDesktopWallpaper` COM 接口（`{B92B56A9-...}` 未注册，QueryInterface 返回
  `E_NOINTERFACE`），传统壁纸 API 在该版本不可用。
- 方案 A（守卫）只是「不让 Windows 换壁纸」，但设置页仍显示幻灯片放映、且一旦 Windows 因其它原因
  重建桌面，窗口照样被销毁。
- **方案 B：把 Unity 窗口从「壁纸层 WorkerW」改挂到「桌面根窗口 Progman」**，
  并把 z 序插到 `SHELLDLL_DefView`（图标层）之下。WorkerW 销毁重建只影响它自己的子树，
  本窗口不在其中 → 得以幸存，无需重启进程。

### 实测层级（WinWatch 工具）
```
Progman [00A1154E]
  ├─ SHELLDLL_DefView [004F0726]   ← 图标层（z 序最上）
  │    └─ SysListView32 [00171BFE]
  ├─ UnityWndClass [00D50580]      ← 本窗口（Progman 子窗口，pid=26472）
  └─ WorkerW [009221FC]            ← z 序最底
```
（改挂前：`Progman → WorkerW → UnityWndClass`）

### 代码改动（`WallpaperController.cs` + `User32.cs`）
1. `AttachToDesktopCore()`：
   - 删除「查找/重试/失败回退 WorkerW」整块，只保留 `SpawnWallpaperWorkerW(progman)`
     （维持 Windows 预期的桌面结构，不再作为父窗口）
   - `SetParent(unityWindow, progman)` + `SetWindowPos(unityWindow, insertAfter=SHELLDLL_DefView, ...)`
   - 铺满尺寸取自 `GetClientRect(progman)`（精确等于桌面覆盖区域，绕开分辨率/DPI 误差）
   - 新增 `SetParent` 失败回退：`!setParentOk || GetParent() != progman` → `RestoreToWindow()`
     并 return，杜绝「全屏顶层窗口盖住图标」的老故障
   - 缓存 `m_DefView`
2. `EnsureClientSize()` 增加 `insertAfter` 参数（原用 `HWND_BOTTOM` 会把窗口压到 WorkerW 之下，
   与「图标层之下」语义不一致）
3. `Update()` 新增 z 序再断言（每 5 秒）：
   - 重新 `FindWindowEx(GetParent(), "SHELLDLL_DefView")`（图标层可能被重建，缓存句柄会失效）
   - `GetWindow(unityWindow, GW_HWNDPREV)` 取上方相邻窗口，若不是图标层就
     `SetWindowPos(..., NOMOVE|NOSIZE|NOACTIVATE)` 重新插到图标层之下
   - 本窗口位于最顶层时 `GW_HWNDPREV` 返回 NULL，同样需校正
4. 注释/日志同步：类注释、存活守护注释、`RelaunchSelf` 注释、挂接成功日志（父窗口=Progman）
5. `User32.cs` 新增 `GetWindow(IntPtr, uint)` P/Invoke + `GW_HWNDPREV` 等常量
   （注意：原有 `User32.GetWindow(string)` 是同名托管辅助方法，靠重载区分）

### 存活守护的语义变化（重要）
- 仍然需要：Explorer **进程**重启会销毁 Progman 及其整棵子树（`DestroyWindow` 递归销毁子窗口），
  本窗口随之被销毁 → 只能重启进程。
- 不再需要：仅 WorkerW 重建（切换壁纸 / 桌面刷新）不会销毁本窗口。

### 验证
- 编译校验（synthcheck）：**0 警告 0 错误**
- 运行中实测（WinWatch `reparent` 直接对运行中的旧实例改挂）：层级变为
  `Progman → SHELLDLL_DefView → UnityWndClass → WorkerW`，`vis=Y`、rect 正确、心跳 `windowVisible=True`
- 真实环境佐证（旧实例 + 手动 reparent，运行 41 分钟无销毁）：
  - `BackgroundType=0`（守卫生效，幻灯片确实已关闭）
  - `TranscodedWallpaper` LastWriteTime 停在 17:21:26（41 分钟未变 → 壁纸没有周期切换）
  - 「设置页显示幻灯片放映」是设置应用 UI 缓存，非功能问题（注册表值与壁纸文件都已证明幻灯片未运行）

## 方案 B 打包验证 + 尺寸膨胀修复（18:00-18:35）

### 新构建验证（Build2026.11.05.18.07.57，PID 6468）
- 层级正确：`Progman → SHELLDLL_DefView → UnityWndClass(pid=6468) → WorkerW`，`vis=Y`
- 日志：`SetParent(3539884, Progman=10556750) 返回 True err=0`、`已挂接为桌面壁纸（父窗口=Progman…）`
- 心跳：`windowVisible=True parent=10556750`，连续 23 分钟无销毁（t=961.7s → t=1381.8s 全 True）
- 守卫：`已记录当前 BackgroundType=2（幻灯片）` → `已关闭系统桌面幻灯片`，运行期稳定为 0

### 触发实验结论（重要）
- `dummy`（WriteBG(2)+广播）、`ab`（2→0+广播）、`wallpaper`（SPI 真实切换壁纸到 img0.jpg 再还原）
  三种触发**全都没有**导致 WorkerW 重建（WorkerW 子 dummy 全部存活）
- 结论：这台机器上「换壁纸」不会销毁重建 WorkerW。之前观察到的销毁要么是实验强力触发、
  要么另有原因。**「WorkerW 重建」的幸存验证无法在本机稳定复现**，只能靠逻辑保证
  （本窗口已不在 WorkerW 子树内，DestroyWindow 递归销毁不到它）+ 长时间后台监视兜底。
- 已启动 40 分钟后台监视（`WinWatch watch 2400`），窗口句柄变化即打印。

### 尺寸膨胀（既有问题，非本次改动引入）
- 现象：窗口从精确的 2720x1080 变成 2736x1119（+16/+39，即 Unity 按「分辨率 + 非客户区」
  重设了窗口尺寸），客户区 = 窗口尺寸（WS_CHILD 无边框），导致壁纸被拉伸、右/下边缘超出屏幕。
- 旧构建（挂 WorkerW）同样出现：Player-prev.log 里 t=7.0s 为 2720x1080，t=66.9s 变 2736x1119，
  之后持续 800+ 秒；是被 WinWatch 手动 reparent 带回的精确尺寸。
- 实测：用 WinWatch `fixsize` 把尺寸改回 2720x1080 后，连续监视 90 秒 Unity **没有**再改回去
  → 是一次性事件，不存在对抗。
- 修复：`Update()` 的 5 秒维护块增加 (a) 尺寸/位置再断言（与 (b) z 序再断言合并）；
  新增 `SWP_NOZORDER = 0x0004` 常量。仅在有偏差时校正，`SWP_NOZORDER | SWP_NOACTIVATE | SWP_FRAMECHANGED`。
