## 补充审查：对照 UGUI 包源码深挖，又发现并修复 3 个缺陷

来源：`Library/PackageCache/com.unity.ugui@1.0.0/Runtime/EventSystem/`（逐行核对源码，而非凭记忆）

### 修复 1：`Process()` 覆写丢了 `usedEvent`（严重）
`StandaloneInputModule.Process()`（第 268 行）真实逻辑：
```csharp
bool usedEvent = SendUpdateEventToSelectedObject();   // true = 事件已被消费
if (!ProcessTouchEvents() && input.mousePresent) ProcessMouseEvent();
if (eventSystem.sendNavigationEvents) {
    if (!usedEvent) usedEvent |= SendMoveEventToSelectedObject();
    if (!usedEvent) SendSubmitEventToSelectedObject();
}
```
原覆写直接调用 `SendUpdateEventToSelectedObject()` 不接返回值 → `usedEvent` 恒 false → **每次点击额外触发方向键导航 + Submit，Button 被重复激活**。已改为接住返回值并 `|=` 累积。

### 修复 2：试图覆写 `ProcessTouchEvents()`（会编译失败）
它实际是 **private**（第 292 行），不是 protected virtual，覆写直接编译错误。
**正确认知**：它恒返回 `input.touchCount > 0`；`BaseInput.touchCount` 默认转发到 `Input.touchCount`，鼠标环境为 0 → 自然返回 false → 假输入**无需**覆写 `touchCount`，鼠标路径照常执行。已删除错误的 override。

### 修复 3：编辑器 Play 模式会删掉原生输入模块（集成缺陷）
`WallpaperController` 运行时挂 Bridge，Bridge.Awake() **无条件替换** `StandaloneInputModule`。
编辑器直接 Play 时壁纸窗口尚未 `SetParent` 到 WorkerW，是正常顶层窗口、能收鼠标；删掉原生模块后 UGUI 彻底读不到真实鼠标 → **编辑器内测试完全失效**。
**修复**：按 `Application.isEditor` 分流 ——
- 编辑器：保留原生模块，仅设 `inputOverride = 假输入`（真实鼠标 + 注入点击并存）
- 打包：替换为 `WallpaperInputModule`（绕过失焦门禁，壁纸窗口永不获焦所必需）

### 修复 4：`SimulateFullClick` 分两帧投递（语义错误）
原第一帧 DOWN、第二帧 UP。`EndFrame()` 在 LateUpdate 才清状态，第二帧 DOWN 仍为 true → `StateForMouseButton()` 判为 `PressedAndReleased`。
虽能触发点击，但 `clickCount` 会走 `lastPress` 相同分支 → **连续点击被误判为双击**。已改为同帧先压 DOWN 再压 UP。

### 核实为「正确」的关键点（避免误改）
- `m_ForceModuleActive: 1`（场景已配置）→ `ShouldActivateModule()` 恒 true → 模块常驻激活，失焦门禁只拦 `Process()` 内部，不拦调用 ✅
- `BaseInputModule.inputOverride` 是 public set，`input` getter 优先返回它 ✅
- `ExecuteEvents.GetEventHandler<T>()` 沿父链查找，**与 Raycaster 类型解耦** → 3D 物体实现 `IPointerClickHandler` 即可响应 ✅
- 按键索引 0/1/2 与 UGUI Left/Right/Middle 完全对应 ✅
- C/C# 打包格式逐位一致：位 0-7 消息 / 位 8 图标 / 位 9-11 按键 / 位 16 按下 / 位 17-31 滚轮；lParam 位 0-15 X、16-31 Y ✅
- 括号配平（剔除注释行）：Bridge `{77/77} (186/186)`、InputModule `{4/4} (9/9)` ✅

## 修复 8：`WallpaperBaseInput.cs` 缺 `using UnityEngine;`（CS0246）

Unity 编译器实际跑起来后报的**第一个真实编译错误**：
```
Assets\Scripts\WallpaperBaseInput.cs(22,12): error CS0246: The type or namespace name 'Vector2' could not be found
Assets\Scripts\WallpaperBaseInput.cs(25,12): error CS0246: ...
Assets\Scripts\WallpaperBaseInput.cs(33,21): error CS0246: ...
Assets\Scripts\WallpaperBaseInput.cs(35,21): error CS0246: ...
```
**根因**：文件只写了 `using UnityEngine.EventSystems;`。C# 的子命名空间**不会**自动带入父命名空间
（不像 `using UnityEngine;` 能覆盖 `UnityEngine.EventSystems`），所以 `Vector2` / `Vector3` / `Mathf` 等
`UnityEngine` 顶层类型全部找不到。

**修复**：补 `using UnityEngine;`（第 1 行）。

### 由此建立的系统性检查（避免同类问题再犯）
写了一个静态分析脚本，提取每个文件实际引用的 Unity 类型并核对 using 覆盖。
结论：**只有 `WallpaperBaseInput.cs` 是真问题**，其余 7 个文件全部 OK。
其余文件报出的「缺失」均为误报，已逐一核实：
- `WallpaperClickQueue.cs` / `WallpaperInputBridge.cs` 的 `Button` → 是自定义结构体字段名，非 `UnityEngine.UI.Button`
- `WallpaperClickTestMenu.cs` 的 `EventSystem` / `GraphicRaycaster` / `PhysicsRaycaster` → 代码里写的是**完整限定名** `UnityEngine.EventSystems.X`，无需 using
- `Text` → 只出现在 `System.Text.StringBuilder` 中，非 `UnityEngine.UI.Text`

### 教训
写 C# 文件时，**`using UnityEngine;` 必须显式写**，不能依赖 `UnityEngine.EventSystems` 之类的子命名空间间接覆盖。
`Vector2` / `Mathf` / `Debug` / `Time` 这些高频类型全在 `UnityEngine` 顶层。
