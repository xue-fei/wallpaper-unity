# 2026-10-29 工作日志

## WallPaper 壁纸程序：Explorer 重启后壁纸消失的恢复方案（方案切换）

### 背景
壁纸窗口是 Explorer 桌面 WorkerW 的子窗口，Explorer 重启会销毁 WorkerW 子树，
Unity 默认处理 WM_DESTROY 直接结束进程 → 壁纸消失。

### 关键结论（实测）
- WorkerW 是 **Progman 的子窗口**（Win11 raised desktop），`EnumWindows` 只枚举顶层窗口，
  必须用 `EnumChildWindows(progman, ...)`。
- WorkerW 由 `0x052C` 消息创建（`SendMessage(progman, 0x052C, 0xD, 0x1)`）。
  **Explorer 重启后新 WorkerW 不会自动出现** → 用「轮询 WorkerW 是否出现」判断是循环依赖，永远为假。
- `Process.GetProcessesByName("explorer")` 在 IL2CPP/HybridCLR 下不可靠（实测未返回新进程）。
- **Explorer 重启后本进程主线程存活**：日志实证心跳持续到 t=5280s，窗口只是变孤儿
  （`windowVisible=False`、`GetParent()==NULL`），进程不退出。→ 这是「不重启进程」方案成立的前提。
- IL2CPP 硬约束：传给原生 API 的托管回调必须标 `[MonoPInvokeCallback(typeof(...))]`。

### 方案切换：从「重启进程」改为「重新走挂接逻辑」
用户提出：「检测到 Explorer 重启后，等几秒 重新走壁纸 逻辑不行吗？」
理由：不重启进程、不依赖「新 Explorer 判定」、不会双开进程白烧 GPU、主线程已确认存活。

### 重挂接的可靠性依据
`AttachToDesktopCore` 首行就是 `originalParent = User32.GetParent(unityWindow)`（孤儿时为 NULL），
后续流程不依赖原父窗口；样式从 `GetWindowLong` 现场读取并重设，
`SetParent(unityWindow, workerW)` 可正常把孤儿窗口挂到新 WorkerW。

### 重试上限（17:12 追加）
用户要求「重试 5 次失败就放弃」，已实现：
- 新增 `private int m_ReattachRetryCount;` 与 `private const int REATTACH_MAX_RETRY = 5;`
- 首次挂接失败后 count=0、timer=2s；每次重试前 count++（1→5）并重试；
  count>=5 时输出 `已重试 5 次仍失败，放弃自动恢复` 并停止。
- 合计：首次 + 5 次重试 = 6 次挂接尝试，最多再等 10 秒。
- 放弃后窗口处于 `RestoreToWindow()` 回退的普通顶层窗口模式，看门狗线程已退出，
  只能重启程序恢复（托盘菜单只有 隐藏/显示/退出，无手动重挂接项）。

### 17:39 诊断日志定案：窗口被销毁，「重挂接」方案不成立
加诊断日志后测出决定性证据（首次挂接 vs 重挂接对比）：

| 阶段 | 日志 |
|---|---|
| 首次挂接 | `parent=0 style=0x14CA0000 visible=True isWindow=True` → `SetParent 返回 True err=0 GetParent=721726 style=0x44000000` ✅ |
| 重挂接 | `parent=0 style=0x00000000 visible=False isWindow=False` → `SetParent 返回 False err=0 IsWindow(workerW)=True GetParent=0 style=0x00000000` ❌ |

**根因：`isWindow=False`** —— Explorer 重启销毁 WorkerW 时，Unity 窗口（WorkerW 子窗口）
**被一并销毁**。Windows `DestroyWindow` 会递归销毁子窗口。
进程仍存活（心跳持续），但窗口句柄已失效，`SetParent` 无法成功。

**结论：「重新走挂接逻辑」在物理上不成立（窗口已不存在），只能重启进程。**

### 最终方案：看门狗 + 重启进程（17:39 实施）
- 恢复 `RelaunchSelf()` / `ShouldRelaunchByBackoff()`（60 秒 5 次防抖）/ `TryMarkRelaunched()` / `m_SelfTerminate`。
- 移除 `m_NeedReattach` / `m_ReattachRetryTimer` / `m_ReattachRetryCount` / `REATTACH_MAX_RETRY`。
- 看门狗流程：`WaitForSingleObject` 返回 → 检查用户退出/关机 → `NewDesktopReady(pid,10000)`
  （轮询 Progman PID 变化 / Shell_TrayWnd）→ `Sleep(2000)` → `TryMarkRelaunched() && RelaunchSelf()`
  → 置 `m_SelfTerminate = true`。
- `Update()` 恢复 `m_SelfTerminate` → `Application.Quit()` 自退。
- `NotifyIconItem.WM_DESTROY` 恢复调用 `RelaunchSelf()`，用 `TryMarkRelaunched()` 与看门狗互斥（冗余备份）。
- `User32.cs` 新增 `IsWindow` P/Invoke 声明。
- 保留诊断日志：`AttachToDesktopCore` 开头（parent/style/visible/isWindow）、
  `SetParent` 返回值+错误码、心跳增加 `parent` 字段。

### 18:00 修复：Process.Start 改用 CreateProcess + ShellExecute 备用

  `ShellExecute(hwnd, lpOperation, lpFile, lpParameters, lpDirectory, nShowCmd)` + `SW_SHOWNORMAL=1`；
  返回值 > 32 为成功。

  再 `Environment.Exit(0)`，防止窗口已销毁时 `Application.Quit()` 不生效导致旧进程空转。
