# 2026-11-03 工作日志

## 壁纸程序： Explorer 重启后壁纸不恢复 —— 时序重构（核心修复）

### 纠正昨天的结论
昨天记录「双实例可同时存活，排除多实例冲突」是**误判**。后来细查发现：
- 先启动的 A：`MainWindowHandle=0` → 已挂接为 `WS_CHILD` 子窗口（正常）；
- 后启动的 B：句柄非 0 → **仍是顶层窗口、从未挂接**，即卡死。

### 真正根因（实测）
**第二个 WallPaper 实例在第一个实例存活期间永远无法完成 Unity 引擎初始化**：
- 内存恒 ~21.2MB、CPU 时间恒定（0.0625s）、无任何 `Player.log` 输出；
- 持有已创建的顶层窗口句柄，但永不挂接；
- 无崩溃转储 / WER / Application 错误事件 → 是**阻塞等待**，不是崩溃；
- `IsProcessAlive(pid, 8000)` 只证明「进程句柄未 signaled」，**无法识别这种卡死**，
  旧进程因此误判新实例"稳定运行"而退出 → 壁纸永久消失。

### 本次修改（方案：旧进程先退出，再由独立启动器拉起新实例）
1. `User32.cs` 新增：`GetCurrentProcessId()`、`CREATE_NO_WINDOW=0x08000000`、`STARTF_USESHOWWINDOW`。
2. `WallpaperController.RelaunchSelf()` 改为调用 `TrySpawnDetachedLauncher(exePath, myPid, ...)`：
   - 在 `%TEMP%` 写 `wallpaper_relaunch_<pid>.cmd`；
   - 脚本轮询 `tasklist /fi "PID eq <pid>" /nh | findstr "<pid>" | findstr /i "<镜像名>"`，
     确认旧进程真正消失后再 `start "" "<exePath>"`；
   - 用 `CreateProcess` 静默启动 `cmd.exe /c "<脚本>"`（先试 `CREATE_BREAKAWAY_FROM_JOB|CREATE_NO_WINDOW`，
     失败退化为仅 `CREATE_NO_WINDOW`），保证启动器不随旧进程消亡；
   - CreateProcess 均失败时，备用 `ShellExecute` **打开同一脚本**（绝不直接开 exe）。
3. 新增 `RequestSelfTerminate()`；`NotifyIconItem` 的 WM_DESTROY 路径在 `RelaunchSelf()` 成功后调用它。
   —— 旧进程必须退出，否则启动器会一直空等。
4. 删除已被取代的 `TryCreateProcess()` / `IsProcessAlive()`。

### 关键实现细节（踩坑记录）
- `find.exe` 在当前环境参数解析异常（恒返回错误码），导致脚本误判"父进程已退出"；改用 `findstr`。
- 批处理括号块内 `%n%` 取到进入块前的旧值 → 必须 `setlocal enabledelayedexpansion` + `!n!`。
- 计数器超上限时 `goto do_launch`（fail-open），避免旧进程意外存活时永不恢复。
- 第二道 `findstr /i "<镜像名>"` 防止 PID 被其他进程复用导致空等。

### 验证
- 自研 .NET 校验程序（与真实代码同样走 `CreateProcess`）模拟「受害者进程退出」模型：
  - 旧进程立即退出：启动器 0.34s 放行并执行后续动作 ✔
  - 旧进程存活 4s：启动器等到其退出后 ~4.29s 放行 ✔
- 整个 HardCode 程序集（含 DOTween/URP 引用）等效编译：**0 警告 0 错误**。

### 待办
- 用户重新打包后实测：重启 Explorer，确认启动器在旧进程退出后拉起唯一新实例并完成挂接。
- 诊断日志（`[Heartbeat]` / `[ExitTrace]` / `[Reattach]`）验证通过后清理或降频。
- 遗留：`WallpaperDemoUI` / `UICamera` 脚本引用丢失；`QualitySettings.asset` 三档丢失管线资产引用。

## 第二轮：旧进程「假退出」——Application.Quit 在窗口被销毁后卡死

### 现象（用户实测反馈）
- 重启 Explorer 后：WallPaper 进程仍在，但壁纸不显示、托盘图标消失；
- 手动杀掉该进程 → 启动器立刻拉起新实例，壁纸恢复正常；
- 再杀掉新实例 → 不会再起（启动器已消费，属预期）。

### 定位（结合 Player.log / Player-prev.log / %TEMP% 现场）
- `%TEMP%\wallpaper_relaunch_46428.cmd` 存在（10:05:44）→ 启动器确实创建并一直等待旧 PID 46428；
- 旧进程日志最后一行是 `Update()` 的「旧进程主动退出」，**之后没有 `OnApplicationQuit` / `OnDestroy`**；
- 托盘图标消失是假象：托盘图标的回调窗口是 Unity 窗口，窗口被 Explorer 销毁后系统自动移除图标，并非 OnDestroy。
- 结论：**`Application.Quit()` 在 Unity 窗口被外部销毁后卡死**，旧进程长期存活 → 启动器空等 → 壁纸不恢复。
  `Thread.Sleep(1000) + Environment.Exit(0)` 兜底因 Quit 卡住而永远执行不到。

### 本次修改
1. `User32.cs` 新增 `GetCurrentProcess()` / `TerminateProcess()`。
2. `WallpaperController.Update()` 的 `m_SelfTerminate` 分支改为**直接硬终止**：
   `TerminateProcess(GetCurrentProcess(), 0)`，失败再退化 `Environment.Exit(0)`；不再调用 `Application.Quit()`。
   理由：窗口已被销毁，无需优雅退出；必须保证旧进程立刻消失，启动器才能放行。
3. 启动器脚本加**超时强杀兜底**：轮询 20 次（约 20s）仍见旧进程（PID + 镜像名双重匹配）→
   `taskkill /F /PID <pid>`（**不加 /T**，否则会连启动器自己一起杀）→ 等 2s → 启动新实例，
   并在 `wallpaper_relaunch_<pid>.log` 记录强杀事件。

### 验证
- 启动器三档场景全部通过（自研 .NET 程序 + CreateProcess，脚本与真实代码逐字一致）：
  - 旧进程立即退出：0.44s 放行；
  - 旧进程存活 4s：4.50s 后放行（确认等到退出，不提前启动）；
  - 旧进程卡死 60s：约 7s（沙箱内 timeout 偏快，真机约 20s）后 `taskkill` 强杀并放行，
    force-kill 日志正确写出，victimExited=True。
- 整个 HardCode 程序集等效编译：**0 警告 0 错误**。
- 清理了测试残留的裸 cmd.exe（PID 33636）。

### 待办

  若仍异常，检查 `%TEMP%\wallpaper_relaunch_<pid>.log` 是否出现 force-kill 记录。

  连续心跳 1310s（22 分钟）稳定运行；
