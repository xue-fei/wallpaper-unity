## 把散落的 DllImport 统一收进 User32.cs

**背景**：项目里 P/Invoke 声明散落在三处——`User32.cs`（主体）、`WinScreenInfo.cs`（3 个 user32 声明，且显示器枚举 API 从未被调用）、`Shell_NotifyIconEx.cs`（shell32 托盘 + 与 User32 重复的 `SetForegroundWindow`/`GetModuleHandle`/`LoadIcon`）。

**改动**：
1. `User32.cs` 新增统一区：
   - 屏幕/显示器：`GetSystemMetrics`、`GetVirtualScreenSize`（干净的帮手，取代 WinScreenInfo 里那个带废变量的版本）、`Rect`/`MONITORINFO`/`MonitorEnumProc`（连同未使用的 `EnumDisplayMonitors`/`GetMonitorInfo` 一并迁入）。
   - Shell 托盘：`NOTIFYICONDATA` 结构体（从 Shell_NotifyIconEx 迁来，改 public）、`Shell_NotifyIcon`、`ExtractAssociatedIcon`、`LoadIcon`。
2. 删除 `WinScreenInfo.cs`（及其 .meta）——唯一对外方法 `GetVirtualScreenSize` 已迁入 `User32`；`WallpaperController.Start` 调用点改 `User32.GetVirtualScreenSize`。
3. `Shell_NotifyIconEx.cs`：删除全部 `DllImport` 与 `NOTIFYICONDATA`，方法改调 `User32.Shell_NotifyIcon`/`User32.LoadIcon`；删除与 User32 重复的 `SetForegroundWindow`/`GetModuleHandle` 及从未使用的 `ExtractIcon`。`WM_NOTIFY_TRAY`/`uID`/`SystemIcons` 等常量与托盘逻辑保留。
4. `NotifyIconItem.cs:45`：`Shell_NotifyIconEx.ExtractAssociatedIcon` → `User32.ExtractAssociatedIcon`。

**注意**：删除 .cs 后需让 Unity 重新生成 `Assembly-CSharp.csproj`（自动）。多屏显示器枚举 API 目前仍是死代码，仅作储备。

## 删除 WallpaperBaseInput.cs 死代码

**背景**：`WallpaperBaseInput : BaseInput` 是早期「把钩子假输入塞进 BaseInput 让 StandaloneInputModule 读取」方案的产物。该方案因 `input` 属性 IL2CPP 下只读、反射 `m_Input` 失败而废弃，改用 `WallpaperInputModule` 完全接管 `Process()`（队列→自 raycast→ExecuteEvents，不读 `input` 属性）。

**现状**：全项目 grep `WallpaperBaseInput` 仅自身引用，从未 `new`/挂 `EventSystem.inputOverride`/`input`，属纯死代码（`WallpaperInputModule : StandaloneInputModule`，不继承它）。

**改动**：删除 `WallpaperBaseInput.cs` 及 `.meta`。`WallpaperInputModule` 与事件链路不受影响。

**当前核心架构**：`WallpaperController`（Win32 钩子/挂接/铺满）+ `WallpaperInputModule`（Unity 内 UGUI 派发）两个文件。

### 修 bug：鼠标 Y 轴翻转（上下镜像）
- 现象：传入 Unity 的鼠标位置上下翻转。根因：GDI 客户区坐标是 Y 向下（左上原点），Unity Screen 是 Y 向上（左下原点），之前直接把 GDI 的 `py` 塞进 `PointerEventData.position` 未翻转。
- 修复：`WallpaperController.MouseHookCallback` 在 clamp 后、switch 前 `py = client.bottom - py`（`client.bottom`=客户区高度，纯 GDI 值，线程安全）；所有 EnqueueMove/EnqueueButton 统一受益。`WallpaperInputModule` case 0 注释更正（原先误导写「Y 向下与 Unity 一致」）。
- 之前点击计数正常是因中心区域对称未暴露边缘错位。
