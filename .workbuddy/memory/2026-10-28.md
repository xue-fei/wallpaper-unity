## SimpleWater.shader URP 移植 —— 编译错误修复（d3d11 两处）

用户回传两条 d3d11 编译错误，均已定位并修复：

### 错误 1：`invalid subscript 'w' at line 179`
- 现象：`o.bitangentWS = cross(...) * v.tangentOS.w * unity_WorldTransformParams.w;`
- 根因：我把 `Attributes.tangentOS` 声明成了 `float3 : TANGENT`，但 `TANGENT` 语义**必须是 `float4`**——手性（handedness）存在 `.w`。对 float3 取下标 `.w` 非法。
- 修复：改为 `float4 tangentOS : TANGENT;`（`.xyz` 是切线方向，`.w` 是 ±1 手性）。

### 错误 2：`undeclared identifier 'LerpWhiteTo' at Shadows.hlsl(260)`
- 根因：URP 的 `Shadows.hlsl` 在 `SampleShadowmap()` 里调用 `LerpWhiteTo`，而该函数定义在 core 的 `CommonMaterial.hlsl`，**但 `Shadows.hlsl` 自己不 include 它**（它的 include 只有 `Common.hlsl`、`ShadowSamplingTent.hlsl`、`Core.hlsl`）。URP 官方 `Lit.shader` 之所以能用，是因为先 include 了 `LitInput.hlsl` → `SurfaceInput.hlsl` → `CommonMaterial.hlsl`，属于间接引入。我直接 include `Shadows.hlsl` 就缺了这一环。
- 修复：在 ShadowCaster Pass 内显式补 `#include ".../core/ShaderLibrary/CommonMaterial.hlsl"`，且顺序为 `Core.hlsl` → `CommonMaterial.hlsl` → `Shadows.hlsl`（Core 必须最先，`Shadows.hlsl` 内部还要用 `TransformObjectToWorld` 等）。
- 教训：**URP 的 include 链是"隐式"的**——每个 hlsl 文件都不保证自洽，实际可用符号取决于调用方的 include 顺序。移植时不能假设"include 了 Shadows.hlsl 就能用里面所有东西"。

### 顺带核对（无问题）
- `CommonMaterial.hlsl` 内**无 CBUFFER、无 TEXTURE2D/SAMPLER 声明** → 在 ShadowCaster 里 include 不会与本 shader 的 `CBUFFER_START(UnityPerMaterial)` / 纹理声明冲突。
- `LerpWhiteTo` 有 `real` 与 `real3` 两个重载（后者受 `#ifndef BUILTIN_TARGET_API` 保护），URP 下 `BUILTIN_TARGET_API` 未定义 → 两个重载都可见，无歧义。
- `BEYOND_SHADOW_FAR` / `SampleShadowmapFiltered` / `GetMainLightShadowSamplingData` / `TransformWorldToShadowCoord` / `ComputeCascadeIndex` / `MixRealtimeAndBakedShadows` 均定义在 `Shadows.hlsl` 自身 → 可解析。

### 修复后三 Pass 的 include 链（最终）
- WaterForward: `Core.hlsl` → `Lighting.hlsl` → `DeclareDepthTexture.hlsl` → `DeclareOpaqueTexture.hlsl`
- ShadowCaster: `Core.hlsl` → `CommonMaterial.hlsl` → `Shadows.hlsl`
- DepthOnly: `Core.hlsl`

## SimpleWater.shader —— pow 负底数警告修复

**警告原文**：`pow(f, e) will not work for negative f, use abs(f) or conditionally handle negative values if you expect them`

**性质**：编译器警告（非错误），但指出了真实的语义缺陷。

**根因**：三处 `pow` 的底数都可能为负：
1. `pow(depthDiff + _WaterDepth, _WaterFalloff)` —— `depthDiff` 是 `abs(eyeDepth - clip.w)` 恒 ≥ 0，但 `+ _WaterDepth`（默认 -10）后为负；
2. `pow(depthDiff + _FoamDepth, _FoamFalloff)` —— 同理（`_FoamDepth` 默认 -50）；
3. `pow(NdotH, specPower)` —— `NdotH` 经 `saturate` 已保证 ≥ 0，本身安全。

**为什么危险**：`pow(负数, 非整数指数)` 在 GPU 上是未定义行为（返回 NaN）。原材质 `_WaterFalloff = -10`、`_FoamFalloff = -50`（都是非整数），水比地形深时底数为负 → NaN → **水面出现闪烁黑块/破洞**。

**原版 ASE 的真实语义**（ASE `PowerNode` 生成的代码）：
```hlsl
if (e == 0) { return 1; }
b = (b < 0) ? -abs(b) : b;
return (b < 0 ? -1 : 1) * pow(abs(b), e);
```
即**带符号保护**。我移植时只抄了 `saturate(pow(...))`，漏了这层保护。

**修复**：新增 `SafePow(float b, float e)` 完全复刻 ASE 语义，三处调用全部改用它：
```hlsl
float SafePow(float b, float e)
{
    if (e == 0.0) return 1.0;
    float a = abs(b);
    return (b < 0.0 ? -1.0 : 1.0) * pow(a, e);
}
```
- 唯一保留的裸 `pow` 在 `SafePow` 内部，底数为 `abs(b)` 恒非负 → 编译器不再警告。
- `e == 0` 时返回 1（原版 ASE 的 `_a/_b` 判断在指数为 0 时的行为）。

**注意**：URP 官方 shader 里的 `pow` 都是 `pow(max(x,0), ...)` 或底数已 saturate 的形式（如 `Lighting.hlsl:34` 的 `pow(NdotH, smoothness)`，`NdotH` 由 `saturate` 保证非负）——说明这个警告是 URP 编译器的**静态检查**，只要底数可能被推断为负就会报，即使实际运行时为正。
