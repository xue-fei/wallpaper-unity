## 每日重启日志（重启原因 + 新实例启动）

需求：每天一个日志文件，只记「重启原因 + 重启时间」，重启后新实例启动也要记，
且重启后继续写当天同一个文件。

### 现有重启路径（共两条，都汇聚到 `RelaunchSelf()`）
| 路径 | 触发点 | 场景 |
|---|---|---|
| Explorer 存活守护线程 | `StartExplorerWatchdog` 的后台线程 | Explorer 进程退出/崩溃 |
| `NotifyIconItem.WndProc` 的 `WM_DESTROY` | 窗口被 OS 销毁 | Explorer 重启 / 显示变化 / 锁屏解锁 |

两者都调 `RelaunchSelf()` → `TrySpawnDetachedLauncher()`，成功后才退出旧进程。
所以挂载点选在 `RelaunchSelf()` 内部（`TrySpawnDetachedLauncher` 成功之后）最准确：
防抖失败 / 用户退出 / 系统关机 / 启动器创建失败都不会误记。

### 实现
1. **新增** `Assets/Scripts/HardCode/Wallpaper/RestartLogger.cs`
   - 路径：`Application.streamingAssetsPath`
     （打包后 = `<exe目录>/WallPaper_Data/StreamingAssets/`，用户要求放这里方便查看）
   - 文件名：`restart-yyyy-MM-dd.log`（本地时间，按天）
   - 格式：`yyyy-MM-dd HH:mm:ss | 原因 | 说明`（` | ` 分隔，便于 Excel/脚本统计）
   - API：`Write(reason, detail)`、`WriteStartup()`
   - `lock` 保证多线程安全（看门狗后台线程 / 窗口线程 / 主线程都会写）
   - **`Application.isEditor` 时直接 return**，避免污染 `Assets/StreamingAssets`
2. **`WallpaperController.RelaunchSelf()`** 加 `reason` / `detail` 参数，
   在 `TrySpawnDetachedLauncher` 成功后调 `RestartLogger.Write(reason, detail)`
3. **两个调用点**：
   - 看门狗：`RelaunchSelf("Explorer退出", "Explorer 进程已退出(PID=" + pid + ")")`
   - `NotifyIconItem` 的 WM_DESTROY：`RelaunchSelf("窗口销毁", "WM_DESTROY（Explorer重启/显示变化/锁屏解锁）")`
4. **`WallpaperController.Start()`** 开头调 `RestartLogger.WriteStartup()`
   （记录 `新实例启动 | PID=xxx`）

  `Build/Build<时间>/` 新目录，不受影响
